# Computer Use capability review

[Documentation](../README.md) / [Computer Use](COMPUTER_USE.md)

On November 14, 2026, we compared the Windows window API and browser contracts in the local reference archive with Nexa desktop 0.19.9 and Android 0.3.9 (baseline `b28b5d74`). The following differences are tied to that baseline so the review can be repeated against another release.

## Gaps with operational consequences

1. **Idle and superseded Windows observations.** The baseline advertised a 30-minute lifetime. It removed expired entries when inserting a new one. An idle store could still find an expired token for readback, approval or control. A newer capture of the same window also left earlier, unused captures eligible for input, subject to live target checks. Tests for a fix should distinguish an input token from a consumed token used to request fresh evidence and preserve independent windows, conversations and paged inventories. [Observation store and admission](../../crates/core/src/tools/computer_use_tool.rs), [existing receipt tests](../../crates/core/src/tools/computer_use_tool/tests.rs)
2. **Incomplete accessibility searches.** Both the observation and live target resolver requested a full descendant cache before applying local scan limits. The resolver inspected up to 2,000 entries and could treat a match in that prefix as unique without checking the rest. In a large grid this costs provider work and can hide duplicate targets. A bounded walk should report partial coverage and preserve proof of target identity on the action path. [Windows observation and resolution](../../crates/core/src/tools/computer_use_tool/windows.rs), [Microsoft element retrieval guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-obtainingelements)
3. **Physical-input monitor unavailable.** The baseline reported monitor availability and detected a change in its generation. When a monitor remained unavailable throughout observation and action, input could continue with instantaneous checks and the Stop control, without a retained history of user takeover or physical Escape. The reference window helper rejects guarded input in this state. Observation can remain available while the monitor recovers. [Monitor capabilities](../../crates/core/src/tools/computer_input.rs), [commit-time checks](../../crates/core/src/tools/computer_use_tool.rs)
4. **Rich text and popup evidence.** Document ranges, selected text and a separately rendered popup each need explicit source identity. Capturing text for every control or reading pixels outside a shared window could disclose unrelated content. Representative acceptance cases are a focused rich editor with a selection, a password editor, an owned transient and an overlapping unrelated window. [Windows observation](../../crates/core/src/tools/computer_use_tool/windows.rs), [paired-window grant](../../apps/desktop/src-tauri/src/remote_screen.rs)
5. **What the model receives.** The internal model received a bounded projection of complete Windows controls. External agents received the display summary from the shared dispatcher, losing semantic element IDs and state even when the window capture held them. Separately, large Android node arrays went through generic text truncation, which could split JSON between nodes. Both paths need the same observation handles and explicit omission information as their source, within the model's budget. [Tool dispatcher](../../crates/core/src/agent/tool_dispatch.rs), [external callbacks](../../crates/core/src/agent/external_tools.rs), [interactive projection](../../crates/core/src/agent/tool_scheduler/interactive_context.rs), [phone result](../../crates/core/src/tools/phone_control_tool.rs)

## Changes following the baseline review

- Window observations check their lifetime at read, approval and dispatch. A newer capture of the same window supersedes earlier input tokens independently of callback completion order. An unexpired historical token can still identify the window for a fresh observation. [Observation store](../../crates/core/src/tools/computer_use_tool.rs)
- Window observation and semantic target resolution walk the control view incrementally. When the walk ends early, observation reports incomplete coverage and a semantic input cannot rely on an unproven unique match. Native input requires a working physical-input monitor. Approved observation remains available during monitor recovery. [Windows implementation](../../crates/core/src/tools/computer_use_tool/windows.rs)
- A Windows observation can request bounded selection or visible text from an editor or document through UI Automation. The evidence identifies its source element. Actual availability depends on the application's text provider. [Computer Use guide](COMPUTER_USE.md)
- The live external-agent callback now receives the model-facing observation text. The desktop transcript and duplicate-call receipt retain their display summary. Large Android results preserve complete node IDs, native sensitivity flags and an explicit count of nodes omitted from model context. [External callbacks](../../crates/core/src/agent/external_tools.rs), [context projection](../../crates/core/src/agent/tool_scheduler/interactive_context.rs)
- Native macOS and Linux app-window control, iOS cross-app input, named secondary actions and multi-image transient-window capture remain platform or adapter differences. The Windows unified reference client describes a single-image limit even though the lower-level window API supports multiple images.

The Windows acceptance test exercised a real WPF text editor and password field.
It read the fixture's selected substring and visible text through the window
capture path. A native Win32 EDIT control tested on this machine did not expose
TextPattern. Applications that only expose ValuePattern still return their
existing value evidence. [Native fixtures](../../crates/core/src/tools/computer_use_tool/windows.rs)

## Evidence and replay

Reference archive locations below are relative to its root. The bundled API and skill describe what a client can request. The reverse-engineering reports describe a particular build. The fixture implements selected behaviors independently.

- `agent-desktop/evidence/docs/computer-use/` contains the window skill plus `docs/api.md`, `docs/guidance.md` and `docs/confirmations.md`. The last file records the reference product's approval policy. Nexa has its own admission and permission scopes.
- `agent-desktop/evidence/docs/cua/cua-repl/instructions/windows/` describes the unified client. `agent-desktop/evidence/docs/cua/docs/tinysky-alt-core-cua-repl.md` records the single-region screenshot restriction and platform-specific action support. `agent-desktop/evidence/docs/browser/docs/browser-control-interruption.md` covers browser user takeover.
- `AgentShell-Agent-全量逆向-ComputerUse-Skills-Cursor-换肤.md` §§3–5 covers skill discovery, window control and cursor feedback. §9 records limits on helper selection and cursor evidence. The two supporting reports are `agent-desktop/evidence/REPORT-v3-agent-desktop-deep-anonymized.md` §§3–5 and `agent-desktop/evidence/REPORT-agent-desktop-computer-use-browser-use.md` §§2–3. Application skins and document templates in §6 serve a separate purpose.
- In `sky-cursor-lab`, `lib/helper-io.mjs` models target revisions and bounds, and `lib/arrival-bridge.mjs` models visible-tab arrival. Running `npm test` in the fixture directory for this review passed all 92 tests.
- Five existing Edge browser tests passed against Nexa's production page script. They exercised capture without decoration, operation-specific arrival, nested capture cleanup, pointer motion and click, and drag with takeover. This exercises the page script in a browser. It supplies no measurement of native desktop latency or Android device behavior. [Browser tests](../../apps/desktop/e2e/browser-agent-interaction-runtime.spec.ts)
